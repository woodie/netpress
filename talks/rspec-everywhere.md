# Bring RSpec's Structural Discipline Everywhere

**Track:** Startup

## Abstract

Although I often build projects in Ruby — staying in my comfort zone — I've expanded into Go, Swift, and Kotlin (with AI pairing), and it has worked well when I hold every new project to the same bar for testing and maintainability. This talk is about carrying RSpec's structural discipline everywhere, so we can all work efficiently with AI to generate great code.

## Detailed Description

Ruby development standards are where I draw inspiration. When diving into smartphone application development, Swift and Kotlin are the obvious choice (skipping Flutter/Dart) since pairing with AI makes native ports very achievable. This has worked well for me when every port is held to the same bar: RSpec's context/subject discipline, translated to each language's own idiom. The payoff shows up concretely: side-by-side test output across the Swift and Kotlin apps is visually identical and makes cross-platform feature development painless.

## Why This Talk Matters

AI makes it realistic to build well outside your comfort zone — a Ruby developer shipping real Swift or Kotlin, for instance. That's a genuine opportunity, but only if we're thoughtful about it. Without solid testing discipline, AI-paired development just as easily produces a hot mess of unmaintainable, poorly tested code, faster than ever. The Ruby community already has outstanding instincts for readable specs that document intent, not just assert outcomes. This talk carries that instinct into any language AI helps you reach, so what you ship stays trustworthy and maintainable.
